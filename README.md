# Obsidian → TeamSpirit 工数入力アシスタント（Chrome拡張）

Obsidianのデイリーノート（Markdown）を読み込み、TeamSpiritの「工数実績入力」
ダイアログの入力欄に反映するお手伝いをする拡張機能です。

**登録ボタンは自動では押しません。** 必ず内容を確認してから、自分で
TeamSpirit側の「登録」を押してください。

---

## 1. インストール方法

1. `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をON
3. 「パッケージ化されていない拡張機能を読み込む」→ このフォルダ（`ts-extension`）を選択
4. ツールバーの拡張機能アイコンをクリックすると、専用のウィンドウが開きます
   （このウィンドウはフォーカスが外れても閉じません。もう一度アイコンをクリックすると、
   既に開いているウィンドウにフォーカスします）

ウィンドウの幅・高さは `background.js` の `chrome.windows.create` にある
`width` / `height` の値を変更すれば調整できます（現在は 640×900）。
変更後は `chrome://extensions` でこの拡張の「再読み込み」をしてください。

## 2. デイリーノートのフォーマット(固定)

以下の形式で書かれた部分だけを読み取ります。他の書き方(自然文、「2時間」
「90分」のような表記など)は対象外です。

```markdown
#### 工数
- キーワードまたはジョブコード：H:MM
- キーワードまたはジョブコード：残り時間すべて
```

ルール:

- 見出しは「工数」という文字列であればOKです。`#`の数（見出しレベル）は
  `#`〜`######`のどれでも構いません（例: `## 工数`でも`#### 工数`でも認識します）。
  この見出しの直後から、
  次の見出し（`#`〜`######`のいずれか）が出るまでを工数セクションとして読みます。
- 各行は `- テキスト：H:MM` または `- テキスト：残り時間すべて` の形だけを
  認識します（`*`始まりでも可）。区切り文字は**全角「：」**に固定しています。
  時刻表記(`H:MM`)側は半角「:」を使うため、項目と値の区切り(全角：)と
  時刻の区切り(半角:)を分けることで混同を避けています。
  - `H:MM` は時:分（例: `2:00`、`0:30`、`1:30`）。それ以外の時間表記は無視されます。
    → TeamSpirit側では「直接時間入力」モードに切り替えて、その時間を書き込みます。
  - `残り時間すべて` と書いた行は、時間を指定しません。
    → TeamSpirit側では「％(パーセント)」モードに切り替えて、スライダーを1目盛り
    動かすだけで、値は入力しません（その案件に残りの時間を当てはめる、という
    使い方を想定しています）。UI上のモード表示は「自動」、時間欄には「残り時間」
    というプレースホルダーが表示されます。
- 「テキスト」部分（キーワードやジョブコードなど）は、後述の③で取得したTeamSpirit側の
  案件一覧とあいまい一致でマッチングされます。ジョブコード（`PJ2000...`など）を
  そのまま書いても、名称の一部を書いても構いません。
- ④の確認画面で、各行の「モード」（時間 / 自動）はドロップダウンで
  後から変更することもできます。
- `やったこと` という見出し（`#`の数はいくつでもよい）がある場合、その直後から
  次の見出しまでの内容がそのまま（時間や案件へのマッチングはせず）読み取られ、
  ⑤の反映時に「作業報告」自由入力欄の冒頭に転記されます。見出しが無い場合は
  この部分はスキップされます。

## 3. エイリアス（ジョブコード → 複数キーワード）（任意設定）

ノートの工数行は、まず**エイリアス（ジョブコード → 複数キーワード）**の登録があれば
それを最優先で使います。無い場合のみ、案件名とのあいまい一致にフォールバックします。
**必須ではないので、使わなくても①〜⑤の基本フローは動きます。**

- 拡張機能ウィンドウの一番下にある「エイリアス設定（キーワード → ジョブコード）｜任意」
  という折り畳みセクションを開くと、「ジョブコード」と「キーワード」を登録できます
  （`chrome.storage.local`に保存され、ブラウザを閉じても消えません）
- **1つのジョブコードに対して複数のキーワードをまとめて登録できます。**
  キーワード欄は**全角読点「、」のみ**で区切ってください（カンマや改行では区切れません）。
  例えば「開発部会議」という案件に対して
  `PMデイリー、開発デイリー` のように登録しておけば、
  ノートでどの表記を使っても同じジョブコードに紐付きます。
- ノートの `#### 工数` セクションで、登録したキーワードのいずれかを案件名の代わりに
  書けば、次回以降は確実にそのジョブコードに紐付きます
- 登録したコードが、現在開いているダイアログの案件一覧に無い場合は
  「案件が見つかりません(要ジョブ追加)」と警告が出ます。TeamSpirit側で
  「ジョブを追加」してから、③で案件一覧を再取得してください
- ジョブコード入力欄は、③で案件一覧を取得すると入力補完が使えます

## 4. 使い方

1. **①フォルダを選択** — デイリーノートが入っているフォルダ（Obsidian Vault
   全体でも、その中の`Daily`のようなサブフォルダでも構いません）を一度選ぶと、
   以降は自動で権限を再利用します（プラグイン不要、`File System Access API`使用）。
   アクセス範囲を最小限にしたい場合は、Vault全体ではなくデイリーノート専用の
   サブフォルダを選ぶことをお勧めします。
2. **②デイリーノート読み込み** — 日付を選んで「読み込む」。
   ファイル名は `YYYY-MM-DD.md` を前提に、Vault内を再帰的に探します。
3. **③案件一覧を取得** — TeamSpiritで「工数実績入力」ダイアログを開いた状態で、
   このタブをアクティブにしてボタンを押します。ダイアログ内のジョブコード・
   案件名を読み取ります。
4. **④抽出結果の確認・修正** — 「#### 工数」セクションの各行を読み取り、
   エイリアス→あいまい一致の順でマッチングします。青バッジ＝エイリアス一致、
   薄オレンジ＝あいまい一致でマッチ度が低い、薄赤＝マッチなし（または案件が
   見つからない）なので必ず目視確認してください。各行の説明文・モード（時間 / 自動）・
   時間・マッチ先の案件はその場で編集できます。
5. **⑤反映** — チェックが付いている行を、TeamSpiritの該当する案件行の
   入力欄に書き込みます。
   - **モードが「時間」の行**: 同じ案件にマッチした行は時間を合算して1つの値として
     反映します（例: 「PMデイリー：1:00」と「開発デイリー：0:30」が同じ
     ジョブコードなら、その案件の時間入力欄には合計の`1:30`が入ります）。
   - **モードが「自動」の行**: 時間は入力せず、TeamSpirit側の「％」モードに
     切り替えてスライダーを1目盛り動かすだけを行います（残りの時間をその案件に
     当てはめる、という使い方を想定）。
   - 「作業報告」自由入力欄には、**「やったこと」「工数詳細」という見出しラベル**で
     セクション分けして転記します（チェックボックスでON/OFF可能、デフォルトON）。
     「やったこと」にはノートの「やったこと」見出しセクションの内容をそのまま、
     「工数詳細」には**マッチした案件ごとにグループ化**した元のノートの行を
     ネストした形で入れます。
     例（ノートに`#### やったこと`セクションがある場合）:
     ```
     やったこと
     - MTG参加
     - 要件定義

     工数詳細
     - 開発部会議
       - PMデイリー：1:00
       - 開発デイリー：0:30
     - 軽微な改修
       - 要件定義：残り時間すべて
     ```
     （「やったこと」見出しがノートに無い場合は、その部分は省略され
     「工数詳細」以降だけが転記されます）
   書き込み後、**必ず自分で内容を確認して「登録」を押してください。**
6. **エイリアス設定（任意）** — 拡張機能ウィンドウの一番下にある折り畳みセクションを
   開くと登録できます。使わなくても①〜⑤は動作しますが、よく使う案件があれば
   登録しておくとマッチング精度が上がります（詳細は次の項目を参照）。

## 5. 対象ドメインについて（重要）

`manifest.json` の `host_permissions` は以下を許可しています。

```
https://*.teamspirit.com/*
https://*.force.com/*
https://*.salesforce.com/*
```

TeamSpiritは会社ごとにSalesforceのカスタムドメイン
（例: `xxxx.lightning.force.com`、`xxxx.my.salesforce.com` など）で動いていることが多く、
上記でカバーできない場合があります。実際に使っているURLのドメインが対象外の場合は、
`manifest.json` の `host_permissions` にそのドメインを1行追加し、
`chrome://extensions` でこの拡張の「再読み込み」をしてください。

## 6. TeamSpiritをChromeアプリ化(PWA)している場合

TeamSpiritを「アプリとして開く」設定にしている場合でも、本拡張のウィンドウは
（拡張機能アイコンから開く独立したウィンドウなので）通常通り開けます。
本拡張は**全ウィンドウ（アプリ化した独立ウィンドウも含む）からTeamSpiritのタブを
自動で探す**ようになっているので、下記の手順で操作できます。

1. 拡張機能アイコンをクリックして、本拡張のウィンドウを開く（TeamSpiritのアプリウィンドウの横に並べて配置すると使いやすいです）
2. TeamSpiritはアプリ化した独立ウィンドウの方で開いたままでOK（工数実績入力ダイアログを開いておく）
3. 拡張機能ウィンドウ側で③〜⑤の操作をすると、自動でTeamSpiritのアプリウィンドウ内のタブを見つけて処理します

もし複数のTeamSpiritタブ／ウィンドウが同時に開いている場合は、意図した方が
操作されているか、反映後に必ず目視確認してください。

## 7. 既知の制約・要調整ポイント

- **案件名は画面表示のテキストを優先して取得します。** TeamSpirit内部の隠しinputの値
  （案件コードと名前を`|`で連結したもの）は、英字部分が大文字化されている場合が
  あります（例: 画面表示は`1on1`だが内部値は`1ON1`）。`scrapeJobsInPage`関数は、
  画面に実際に表示されているdivのテキストを優先して案件名として取得し、
  それが見つからない場合のみ隠しinputの値にフォールバックします。
- **時間入力モードの想定が仮説です。** ダイアログ内の各案件行には
  「％スライダー / 時刻範囲 / 直接時間」の3モードがあり、本拡張は
  「直接時間入力」モード（`btnClock2{index}` → `empInputTime{index}`）を
  使う想定で作っています。実際に押してみて、意図した箇所に時間が入らない場合は、
  `sidepanel.js` の `fillEntriesInPage` 関数内のID（`btnClock2Label`、`empInputTime` など）を、
  実際の画面で正しく動くモードのIDに書き換えてください。
- **ノートに書かれていない新規案件は追加されません。** 既存の案件一覧（開いているダイアログに
  表示されている行）にマッチしたものだけ反映されます。新しい案件は
  TeamSpirit側で「ジョブを追加」してから、再度③の取得をしてください。
- **「自動(残り時間)モード」のスライダー操作は動作確認済みです。** ％モードに
  切り替えた後、`sidepanel.js` の `setPercentModeInPage` 関数は
  `window.dijit.registry.byId('empWorkSlider{index}')` でウィジェットを取得し、
  `.set('value', 現在値+1)` を呼んでスライダーを1目盛り動かします
  （キーボード操作のシミュレートなど他の手段は使っていません）。
  もし将来TeamSpirit側の実装が変わってこの方法が効かなくなった場合は、
  ブラウザの開発者ツールのConsoleで `window.dijit` が存在するか確認してください。
- **対象フレーム(iframe)は「推測」ではなく「事実確認」で特定します。**
  TeamSpiritのページには、実際に操作すべきフレームの他に、見た目上は同じ
  要素(`#empWorkTableBody`)を持っていても`window.dijit`などのJavaScript
  グローバル変数へのアクセスが制限されているフレーム(Salesforceのセキュリティ
  機構など)が同時に存在することがあります。本拡張は、まず全フレームに対して
  「`#empWorkTableBody`が存在するか」と「`window.dijit.registry`が使えるか」
  の両方を確認し、**両方を満たすフレームを最優先**で選びます(`checkWorkDialogFrame`関数)。
  どちらも満たすフレームが無い場合のみ、テーブルの存在だけを条件にフォールバック
  します。特定した`frameId`は以降の操作すべてでその1つのフレームだけを対象に
  実行し(`executeInWorkDialogFrame`関数)、複数フレームの結果を集めて多数決の
  ように選ぶ、といった推測は行いません。特定した`frameId`は`state.workDialogFrameId`
  に保存して使い回し、無効になっていたら(ダイアログの再生成などで)自動的に
  再検出します。それでも「ダイアログが見つかりません」というエラーが出る場合は、
  TeamSpiritで「工数実績入力」ダイアログを開いた状態になっているか確認してください。
  （なお、要素取得については見つからない場合に軽く2回だけ短い間隔で
  再試行する程度に留めています。長時間のリトライは根本原因の解決にはならず
  単に処理が遅くなるだけなので、あえて増やしていません。）
- ノートが固定フォーマット（`#### 工数` 見出し + `- テキスト：H:MM` または
  `- テキスト：残り時間すべて`）から外れている場合、その行は無視されます
  （エラーにはならず単に抽出されません）。
- Salesforce Lightning環境では工数入力ダイアログが別フレーム（iframe）内にある場合があります。
  本拡張は開いているタブの全フレームに対して処理を試みますが、うまく取得できない場合は
  ダイアログを開いた状態で少し待ってから再度お試しください。

## 8. ファイル構成

```
ts-extension/
├── manifest.json    # 拡張機能の設定
├── background.js    # 拡張機能ウィンドウを開くための最小限のservice worker
├── sidepanel.html   # 拡張機能ウィンドウのUI(ファイル名は旧仕様のまま)
└── sidepanel.js     # Vault読み込み・パース・マッチング・TeamSpirit操作の本体
```
